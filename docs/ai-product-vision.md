# DeckCraft AI 助手：最终产品形态与交互规范 (AI-Product-Vision)

> **写给后续所有协作 AI 的核心约定**：
> 本文是关于 DeckCraft AI 助手的**唯一产品终态定义**。请勿自行发明“大纲审核控制台”、“多阶段审批流”或“数据依据快照”等复杂中间产物。
> 我们的目标极其纯粹：**用户在聊天框说一句话，左侧立刻多出幻灯片，中间画布直接画出美观、排版工整、可直接编辑和放映的原生 PPT。**

## 二、 核心交互场景 (User Scenarios)

### 场景 1：从零开始，一键生成整套 PPT (Zero to Presentation)
1. **用户操作**：打开空文稿，在右侧输入：`"做一份关于城市微农业的商业提案，大约 5~6 页"`，点击发送。
2. **AI 反馈**：
   - 聊天区显示极简的状态：`正在构思结构与排版...`（耗时约 3~6 秒）；
   - **直接出结果**：左侧缩略图栏瞬间增加 6 张幻灯片；
   - 主画布自动定位到第 1 页（封面），内容完整呈现（不是灰色占位符，而是真实的标题、副标题、装饰形状、色块背景）。
3. **编辑体验**：
   - 用户点击画布上的任意文本（例如把“微农业”改成“都市农场”），光标就地闪烁，直接手打修改；
   - 用户按 `F5`（或点击放映），直接进入全屏幻灯片放映模式；
   - 用户按 `Cmd+S` / `Ctrl+S`，可以导出为标准 `.pptx` 或 `.deckcraft` 文件。

---

### 场景 2：针对单页的自然语言微调 (In-Place Slide Tweaking)
用户不需要用复杂表单，只需要选中某页并打字：
1. **用户操作**：在左侧点击第 3 页（当前是 3 个小卡片），然后在聊天框发：
   `"把当前页改成 2 列对比，左边讲传统模式弊端，右边讲我们模式的优势"`。
2. **AI 反馈**：
   - AI 仅替换当前选中的第 3 页内容；
   - 画布原地重排：变成左右两个对比卡片，文字层级自动对齐；
   - 整个操作支持 `Cmd+Z`（一次 Undo 即可退回原版本）。

## 三、 幻灯片版式库：AI 应该输出什么样的页面？

PPT **绝对不是**白底黑字的 Word 文档。AI 生成的每一页必须具备**视觉层级与版式美感**。
首期支持 5 种最经典、最通用的商业 PPT 模板版式：

### 版式 A：封面页 (Cover Slide)
- **视觉构成**：居中或偏左的大标题（字号 36~44pt）、副标题（20~24pt）、底部元信息（汇报人、日期）。
- **装饰元素**：底部一条主题强调色（Accent Color）色块，或几何边框。

```text
+-------------------------------------------------------+
|                                                       |
|                                                       |
|        大标题：城市微农业商业提案                     |
|        副标题：重塑邻里生态与绿色消费的新模式         |
|                                                       |
|                                                       |
|        汇报人：创新业务组        日期：2026年10月     |
|=======================================================| [主题色色带]
+-------------------------------------------------------+
```

---

### 版式 B：三卡片/分栏页 (3-Column Card Grid) —— 最常用的核心版式
- **视觉构成**：顶部主标题（28pt）+ 简要导语；下方并排放置 3 个浅色背景圆角矩形卡片；
- **卡片内部**：卡片序号或小标题（粗体 16pt）+ 2~3 行精炼要点说明（12~14pt）。

```text
+-------------------------------------------------------+
|  主标题：核心价值主张 (Core Value Propositions)       |
|  通过集约化技术与社区协同，实现生态与经济双重收益     |
|                                                       |
|  +-----------------+ +-----------------+ +-----------------+
|  | [01 空间活化]   | | [02 亲子社群]   | | [03 本地供给]   |
|  |                 | |                 | |                 |
|  | 唤醒闲置屋顶空间| | 开办自然科普课堂| | 新鲜有机果蔬    |
|  | 模块化轻量种植箱| | 建立邻里共建小组| | 零里程冷链损耗  |
|  +-----------------+ +-----------------+ +-----------------+
|                                                       |
+-------------------------------------------------------+
```

---

### 版式 C：两栏左右对比页 (2-Column Comparison)
- **视觉构成**：顶部标题；中间切分为左右两栏（例如：现状 vs 未来 / 弊端 vs 优势）。
- **卡片内部**：左栏用柔和灰色/冷色，右栏用品牌强调色（Accent）边框加亮。

```text
+-------------------------------------------------------+
|  主标题：传统生鲜采购 vs 社区微农业模式               |
|                                                       |
|  +-------------------------+ +-------------------------+
|  | 传统长距离供应链        | | 社区微农业闭环模式      |
|  |                         | |                         |
|  | • 跨省运输，损耗率 > 20%| | • 社区就近采摘，零运费  |
|  | • 经过多级批发，溢价高  | | • 基地直达餐桌，成本低  |
|  | • 无法感知种植与品质源头| | • 全程透明，可追溯体验  |
|  +-------------------------+ +-------------------------+
|                                                       |
+-------------------------------------------------------+
```

---

### 版式 D：大指标/要点数据页 (Key Metrics / Big Numbers)
- **视觉构成**：顶部标题；中间 2~3 个视觉极抢眼的大数字（48pt 粗体）+ 下方指标含义。

```text
+-------------------------------------------------------+
|  主标题：预期运营效益与环境影响 (Impact Forecast)     |
|                                                       |
|     +---------------+   +---------------+   +---------------+
|     |     75%       |   |    2,400+     |   |    3.2 倍     |
|     |  闲置屋顶复用率|   |  社区常住参与户|   |   综合收益溢价|
|     +---------------+   +---------------+   +---------------+
|                                                       |
+-------------------------------------------------------+
```

---

### 版式 E：结束与总结页 (Closing / Call to Action)
- **视觉构成**：简洁有力的总结陈词、合作邀请、联系方式、致谢。

## 四、 技术映射本质 (How it Translates to DeckCraft)

为了防止代码再次陷入过度设计的泥潭，所有参与编码的 AI 必须理解以下极简的技术对应关系：

1. **AI 模型返回的数据必须是简洁的 JSON**：
   模型只需要输出结构化的语义数据，**不负责直接计算坐标和像素**。
   例如：
   ```json
   {
     "theme": "business-modern",
     "slides": [
       {
         "layout": "cover",
         "title": "城市微农业商业提案",
         "subtitle": "重塑邻里生态与绿色消费的新模式",
         "meta": "汇报人：创新业务组"
       },
       {
         "layout": "three-cards",
         "title": "核心价值主张",
         "cards": [
           { "title": "空间活化", "body": "唤醒闲置屋顶与阳台空间，模块化轻量种植。" },
           { "title": "亲子社群", "body": "开办自然科普课堂，建立邻里共建兴趣小组。" },
           { "title": "本地供给", "body": "新鲜有机果蔬就近采摘，零里程冷链损耗。" }
         ]
       }
     ]
   }
   ```

2. **DeckCraft 本地做确定的几何计算 (Layout Engine)**：
   - 16:9 画布尺寸标准固定为 `960 x 540`（或相应比例）。
   - 代码根据 `layout: "three-cards"`，在 Rust 里用极简单的算术算出 3 个矩形的 `Rect(x, y, w, h)`；
   - 直接调用 `doc.slides[i].shapes.push(...)` 添加背景卡片矩形和文字文本框；
   - 填充颜色使用 DeckCraft 现成的主题调色板（`theme.accent`、`theme.card`、`theme.text`）。

3. **没有中间层操作台**：
   - 不搞“先显示大纲，再点确认，再生成形状”的复杂过程；
   - 一键生成，直接写入 Slide 列表；用户如果有不满意的地方，直接用鼠标在画布上改字，或者在聊天框发一句“把第 2 页改成 4 个点”。

## 五、 牢记底线原则 (Dos and Don'ts)

- **DO（坚持）**：
  - 坚持**生成所见即所得的真实 PPT**；
  - 坚持每次生成/修改操作都是一个**原子撤销步**（按一下 `Ctrl+Z` 就能恢复）；
  - 坚持极简代码，核心链路只有一条：`Prompt -> LLM JSON -> Rust Layout to Shapes`。

- **DON'T（严禁）**：
  - **严禁**创建任何“需要用户点击确认才能继续”的独立大纲面板；
  - **严禁**每次对话后生成大篇幅的工作汇报 `.md`、审查 `.md` 或截图文件；
  - **严禁**只返回纯文本标题卡片而不画排版形状。
